# Intent: Code Difference Checker (`/diff`)

## 1. Problem & Persona Context
- **Target Persona Priority**:
  - [ ] 1. Visitor / Recruiter (Priority: First paint, mobile responsiveness, accessibility, intuitive UX)
  - [x] 2. Portfolio as a Work Sample (Priority: Architectural discipline, vanilla ES modules, clean code)
  - [ ] 3. Owner (Priority: Analytics dashboard, Bedrock chat demo, personal utility)
- **Problem Statement**:
  Comparing two versions of a file is the most routine thing an engineer does, and
  the moment you are away from a terminal it is also the most awkward. A config that
  used to work and now does not, a vendor's "updated" SDK snippet against the one in
  your repo, a patch pasted into a ticket by someone who could not attach the branch,
  a minified response that differs from staging in one field. The habitual answer is
  one of a dozen ad-supported diff sites — and every one of them wants you to paste
  both sides of proprietary source into someone else's server. For a production
  config with a connection string in it, that is not a trade worth making.

  **Code Difference Checker (`/diff`)** is a zero-egress, fully client-side answer:
  paste or drop two files, get a real diff — split or unified, with character-level
  highlighting inside changed lines — and copy the result out as a standard unified
  patch. It also reads a patch: paste `git diff` output and the page renders it as a
  proper side-by-side view, which is the half of the problem the paste-two-boxes
  tools never solve.

  As a work sample it is the strongest of the six Dev Tools apps so far, because the
  centre of it is not a wrapper over a browser API. Myers' O(ND) algorithm with the
  linear-space divide-and-conquer refinement, a histogram fallback so a large file
  degrades gracefully instead of hanging, and a token-level refiner that turns
  "this line changed" into "this identifier changed" are genuine algorithmic work,
  written from scratch and tested against known vectors.

## 2. Constraints & Non-Goals
- **Inviolable Constraints**:
  - **ADR-001**: Pure vanilla ES modules. No framework, no component abstraction, no
    runtime npm import. The diff engine, the tokenizer and the patch parser are all
    hand-written — **jsdiff was explicitly considered and rejected** (see §6.4).
  - **ADR-016**: Zero third-party asset requests. Self-hosted Plus Jakarta Sans via
    `fonts.css`, icons from the existing vendored Font Awesome subset.
  - **ADR-023**: Zero AI, zero backend. No `/chat` call, no model, no server compute.
    There is no "explain this diff" button and no semantic summary — the whole point
    is that nothing leaves the tab.
  - **Zero Network Egress**: the page ships `connect-src 'none'`, matching
    `json.html` and `crypto.html` byte for byte in its CSP. No URL fetching, no
    GitHub API, no gist import. This was decided against explicitly: pulling a PR
    would mean naming `api.github.com` in `connect-src`, which is a new third-party
    origin in the SPA's app family and an ADR-016 exception this feature does not
    need.
  - **No `eval` / `new Function`**: nothing on this page constructs executable code.
    The syntax tokenizer is a hand-written lexer over a character stream; the CSP
    carries no `'unsafe-eval'`.
  - **No `innerHTML` on pane content, ever**: both panes hold arbitrary attacker-
    supplied source. Every rendered token is written with `textContent`. See §5.
  - **App Chrome Contract** (`docs/FRONTEND.md` "App chrome"): the shared
    `.app-header` / `.app-footer` DOM shape, the seven `--chrome-*` tokens, and the
    four breakpoint tiers, coloured from this app's own palette.
  - **Apps Shelf Contract**: one `<a class="app-tile reveal">` in
    `<section id="apps">` of `frontend/index.html`, a 1200x630 `diff-preview.png`
    generated by `scripts/generate_social_previews.py`, an eyebrow icon from the
    vendored subset, and the `"in a new tab"` wording in the `aria-label`.

- **Explicit Non-Goals** (each was on the table and was cut deliberately):
  - **Three-way merge**: no base/ours/theirs panes, no conflict markers, no per-hunk
    accept controls. It roughly doubles the state machine and the edge cases, and it
    is a different product — conflict *resolution*, not difference *inspection*.
  - **Folder / multi-file / archive diff**: no directory picker, no `.zip`, no
    file-tree of changed files. Heaviest option by a wide margin and the one least
    likely to be used from a phone.
  - **Semantic JSON/YAML structural diff**: comparing parsed objects with key order
    ignored is a coherent feature and a natural pairing with `/json`'s parsers — it
    is deferred to v1.1, not dismissed. v1 diffs text.
  - **Per-language syntax grammars**: one generic tokenizer ships, not N grammars.
    See §6.3 for what that does and does not get right.
  - **Fetching anything**: no URL, PR, gist or raw-file import. See above.
  - **Persisting pane content by default**: people paste secrets into diff tools.
  - **Editing in place / applying a patch to produce a merged file**: `/diff` reads
    and renders; it does not write a third document.
  - **Server-side endpoints, database rows, analytics events**: none. The page is
    inert from the backend's point of view.

## 3. Impacted Layer Matrix & Quality Gates
- [x] **Frontend**: `npm run lint` && `npm test` && `npm run build`
- [ ] **Backend**: not touched — no route, no service, no schema
- [ ] **Database**: not touched — no model, no migration, `alembic check` unaffected
- [x] **Docs / Hashes**: `python3 scripts/check_csp_hashes.py` && `python3 scripts/check_docs.py --fix --show-tokens`

**Note on the CSP gate**: `check_csp_hashes.py` covers only the three inline
`<script>` blocks in `frontend/index.html`. This change edits `index.html` markup
(the new tile) but no inline script, so the three pinned hashes are unchanged.
`diff.html`, like `json.html` and `crypto.html`, carries its own CSP in a
`<meta http-equiv>` and contains no inline script at all.

## 4. Success Metrics & Verifiable Criteria
- **User-Facing Behaviour**:
  - **Two panes, three tabs.** `/diff` holds one comparison in memory and three
    deep-linkable tabs read it: `#compare` (the two input panes), `#patch` (paste or
    render a unified patch), `#about` (what the engine does and where its limits
    are). Editing either pane re-diffs live, debounced.
  - **Compare (`#compare`)** — paste, drag-and-drop or file-pick into either side
    (5 MB cap, matching `/crypto` and `/json`). Line-level diff with
    character-level intra-line highlighting, so a one-identifier change reads as a
    one-identifier change rather than a whole red/green line pair. Toggles for
    ignore-whitespace, ignore-case, ignore-blank-lines and trim-trailing. A
    split/unified view switch that collapses to unified automatically below 640px.
    Collapsed unchanged regions with a "N unchanged lines" expander. Prev/next
    change navigation by keyboard (`j`/`k` and arrow keys) and a change counter
    reading `+12 additions · -7 deletions · ~3 modified`. Synchronised scrolling
    between panes. One-click copy of the result as a standard unified patch, and a
    download.
  - **Patch (`#patch`)** — paste `git diff` / `diff -u` output, or drop a `.patch`
    or `.diff` file, and the page parses the hunk headers and renders it in the same
    split/unified viewer. Malformed hunks are reported with a `line:column` and a
    caret rather than silently half-rendered.
  - **Syntax tinting** — one generic lexer handles strings, the three comment
    dialects (`//`, `/* */`, `#`), numbers, punctuation and a shared keyword set,
    which covers the C family, JS/TS, Python, Go, Java, SQL, JSON and YAML well
    enough to read. Diff colour always wins over token colour where the two
    compete, because the diff is the signal.
  - **Privacy** — view mode, the four whitespace toggles and theme persist in
    `localStorage`; pane content does not, unless the visitor flips a **"remember my
    panes"** switch that defaults to **off**. A "Clear both" button wipes panes,
    results and the stored copy in one action. This mirrors `/json` exactly.
  - **Ergonomics** — full keyboard reachability, `theme` shared with the SPA so a
    visitor who chose light on the portfolio arrives here in light, and every target
    at least 44x44 at mobile tiers (WCAG 2.5.5).
- **Deterministic Quality Gates**:
  - [ ] `npm test` passes, with new suites covering the diff engine (including known
        Myers vectors and the identical / empty / one-side-empty degenerate cases),
        the intra-line refiner, the unified-patch writer, the patch parser
        (including malformed hunk headers), and the tokenizer.
  - [ ] A **round-trip property test**: for a generated pair of documents,
        `applyPatch(a, writePatch(diff(a, b))) === b`. This is the single assertion
        that proves the engine and the emitter agree, and it is what catches an
        off-by-one in a hunk header that eyeballing never will.
  - [ ] A test asserts a pane containing `<img src=x onerror=alert(1)>` renders as
        visible text and executes nothing.
  - [ ] `npm run lint` passes (ESLint over `frontend/js/diff/*.js` after the
        `lint:js` glob is extended, Stylelint over `diff.css`).
  - [ ] `npm run build` passes **including its size budget gate** — see §5.1, this
        is the gate most likely to fail.
  - [ ] `python3 scripts/check_docs.py --fix --show-tokens` reports no drift, with
        every new module in `docs/JAVASCRIPT.md` and every new test in
        `docs/TESTING.md` at its real line count.
  - [ ] `python3 scripts/check_csp_hashes.py` passes unchanged.

## 5. Risks & Mitigations

### 5.1 Bundle size budget — the binding constraint, and it is tighter than last time
- *Risk*: `scripts/build.mjs` enforces `BUDGETS_KIB = { js: 355, css: 265 }`. A
  build of `main` right now reports:

  | | Used | Budget | Headroom |
  | :--- | ---: | ---: | ---: |
  | JS | 346.6 KiB | 355 KiB (98%) | **8.4 KiB** |
  | CSS | 262.6 KiB | 265 KiB (99%) | **2.4 KiB** |

  For calibration, the three sibling Dev Tools apps cost, as built:
  `/json` 46.4 KiB JS + 16.5 KiB CSS, `/cron` 28.2 + 22.8, `/crypto` 18.5 + 19.4.
  `/diff` is projected at **~30 KiB JS + ~18 KiB CSS**. A seventh app does not fit
  in 8.4 KiB and 2.4 KiB. The budget gate *will* fail unless it is addressed in the
  same change.
- *Mitigation*: raise the ceilings deliberately to `{ js: 390, css: 285 }` and amend
  the rationale comment above them in the same commit, which is the procedure that
  comment prescribes. The budget exists to force the argument to be made out loud,
  not to freeze the site at six apps.
- *The alternative, and why it is not bundled here*: `arcade.css`, `cron.css`,
  `crypto.css` and `json.css` each carry their own copy of the app-chrome rules —
  roughly 10 KiB of near-identical CSS repeated four times. Extracting it to a
  shared `app-chrome.css` would reclaim most of what `/diff` needs on the CSS side
  and is already identified in that same rationale comment. It is also a refactor
  touching four shipped apps and four visual regressions' worth of risk, and
  smuggling it into a feature commit is how both changes become hard to review.
  **Recommendation: raise the ceiling now, file the chrome extraction as its own
  change.** Flagged for the approval decision — say the word and it lands here
  instead.

### 5.2 Diff performance on large inputs
- *Risk*: naive Myers is O(ND) in the edit distance. Two 5 MB files that share
  almost nothing have an enormous D, and the tab locks — the visitor's impression of
  the site becomes a frozen page.
- *Mitigation*: three layers. (1) Common prefix/suffix stripping before the engine
  runs at all, which collapses the usual "one line changed in a big file" case to
  near-nothing. (2) A configurable work ceiling on the Myers loop; when it is
  exceeded the engine falls back to a histogram/patience diff, which is O(N log N)
  and produces a *good* diff rather than a *minimal* one. The UI says which
  algorithm produced the result rather than pretending. (3) A 5 MB input cap with a
  clear rejection notice, debounced recomputation, and rendering only the visible
  window plus collapsed unchanged regions.

### 5.3 Correctness of the hand-written engine
- *Risk*: a unified patch with an off-by-one in a hunk header applies cleanly to the
  wrong place and silently corrupts a file. That is worse than emitting nothing.
- *Mitigation*: the round-trip property test in §4 is the primary defence, plus
  fixed vectors for the degenerate cases (identical files, empty file, no trailing
  newline, CRLF against LF, a file that is one long line) and a
  `\ No newline at end of file` marker emitted and parsed correctly.

### 5.4 Security / DOM injection
- *Risk*: this page's entire input surface is untrusted text that the visitor
  *wants* rendered, and a diff viewer that builds HTML strings is a stored-XSS
  machine the moment someone shares a permalink. (It cannot, here — nothing is
  shared or stored server-side — but the habit is what matters.)
- *Mitigation*: no `innerHTML` interpolation anywhere in `js/diff/`. Token spans are
  created with `document.createElement` and filled with `textContent`. DOMPurify is
  not needed and is not loaded, because no HTML string is ever constructed.

### 5.5 API Cost / Rate Limits
None. Zero Bedrock calls, zero database queries, zero API requests of any kind.

### 5.6 First paint / SPA impact
None. `/diff` is a separate esbuild entry on a separate page, sharing no module with
the SPA, so nothing enters the service worker's shell graph and `index.html`'s
critical path is unchanged. The SPA's only delta is one static tile with a lazily
loaded image.

## 6. Assumptions
1. **`/diff` is the route**, served from `diff.html` by the existing extensionless
   rewrite in `frontend/.htaccess` (rule 3) — no new rule required. One alias is
   added for parity with `/regex`, `/encode`, `/yaml` and `/jsonpath`:
   `/patch` -> `/diff#patch`.
2. **Eyebrow is "Dev Tools"** — the same category as `/cron` and `/json`.
3. **Icon**: `fa-code-compare` is the semantically exact glyph and is **not
   currently in the vendored subset**. `scripts/vendor_fonts.py` scans the source
   for `fa-*` classes actually used, so re-running it after the markup lands adds
   the glyph automatically — at the cost of a regenerated `woff2` and a changed
   `fonts.css`. *Assumption taken: re-run it.* The zero-churn fallback is to reuse
   `fa-code` (already in the subset, already the `/cron` eyebrow) for both the tile
   and the brand icon.
4. **jsdiff was considered and rejected.** It is battle-tested and would have been
   faster to ship, but it costs ~12 KiB against 8.4 KiB of headroom, adds a third
   vendored dependency to audit alongside DOMPurify and marked, and hollows out the
   "written from scratch, no third-party code" claim the rest of the Dev Tools shelf
   makes. The algorithm is the work sample here; outsourcing it outsources the point.
5. **Theme follows the SPA** via the shared `theme` localStorage key, resolved in
   `diff-main.js` the way `json-main.js` does it, with `<meta name="theme-color">`
   kept in sync.
6. **The preview card** is generated, not drawn by hand: `frontend/diff-preview.html`
   plus a `"diff"` entry in the `PAGES` map of `scripts/generate_social_previews.py`,
   rendered to a 1200x630 `diff-preview.png` through the pre-installed Chromium.
7. **Structural JSON/YAML diff is deferred to v1.1**, not dropped. It would reuse
   `js/json/json-parser.js` and is specified as a follow-on. Flagged for the
   approval decision — say the word and it lands in v1.
